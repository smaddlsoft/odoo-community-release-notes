Odoo 20 for Community users Draft

How items were classified

The feature list follows the items of Odoo’s official release notes. Each item was read and assigned by hand to the module(s) it belongs to. Each module’s edition comes from the module lists of a Community and an Enterprise 20.0 test database: LGPL-3 means Community, OEEL-1 means Enterprise. Evidence was then collected per item and conflicts were reviewed:

  • UI text: distinctive phrases of the item (its title, quoted labels) looked up in each module’s translation template, which holds all user-visible texts of the module;
  • Code: a search pattern written for the item, run over the public Community source and over a licensed Enterprise copy searched locally (only module names are reported);
  • Test database: checks on the 20.0 test databases (models, fields, selection values, removed modules) and screenshots of the Community interface;
  • Dependencies: for industry packages, whether their dependency tree contains Enterprise modules.
ConfidenceExact meaning
VerifiedA direct check backs the status: a distinctive UI text of the item occurs only in the named module(s) (at most four match); a code search written for this item hits the named module; a test-database check or a Community screenshot confirms it; the item belongs to an app that exists only as Enterprise module(s), so nothing of it can be in Community; or an industry package depends on Enterprise modules.
Module-levelThe module the feature lives in is known and its edition verified, but no direct match was found for this particular item. Main risk: a Community app item whose screen actually comes from an Enterprise extension module.
Needs reviewA judgement call without direct evidence: the item probably spans Community and Enterprise and the parts could not be pinned down, or it bundles many changes (most localizations cover accounting, payroll and point of sale of a country in one item).

Each item’s “Evidence” list shows the exact checks behind its status.
